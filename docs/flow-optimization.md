# 主流程简化说明

- 更新日期：2026-10-31
- 范围：添加主机、新建专服、世界配置、MOD 添加与应用

## 1. 已合并且不再要求用户单独点击的步骤

### 新建专服

旧流程：

```text
新建专服 → 填写 → 预览 → 确认 → 创建容器
```

现在：

```text
新建专服 → 填写 → 创建专服
```

`preview_instance_create` 命令和前端预览窗口已删除。点击“创建专服”只调用一次 `create_instance`：后端先在同一命令内完成只读检查（HostTarget、Release、端口证据、注册表、Docker/Compose、管理目录），通过后立即在注册锁内分配实例与端口并接纳持久创建任务。阻断项以 `CREATE_BLOCKED` 返回并按白名单显示在同一对话框；没有“重新检查”或“返回编辑”中间步骤。创建成功后从列表提示进入世界配置页。

创建表单中的“创建后启动”已移除。该选项此前没有对应的启动执行，容器创建后应由世界配置应用流程决定是否启动。

### 世界配置

旧流程：

```text
编辑 → 保存期望配置 → 预览应用 → 应用配置
```

现在：

```text
编辑 → 保存并应用
```

保存并应用会先保存期望配置，再调用一次 `apply_world_config`：后端在同一命令内完成应用检查（revision、期望摘要、Token、部署、Release、渲染），有阻断项时以 `WORLD_APPLY_BLOCKED` 返回并内联显示，不再弹出应用预览窗口。前端已移除“预览应用”入口；仍保留“仅保存”作为次要操作。应用结果携带的警告（release 未通过隔离运行验证、已有存档时世界生成选项只对新世界生效）显示在操作反馈中。

### MOD

旧流程：

```text
添加 MOD → 保存期望 → 准备内容 → 等待
→ 自动保存固定摘要 → 应用预览 → 应用 → 运行验证
```

现在：

```text
主机 MOD 库添加/下载内容
→ 实例“主机库”选择版本
→ 应用更改
```

实例不再执行 per-instance 下载；内容由主机库提供。已有 MOD 的变更使用“应用更改”，预览通过后直接提交应用任务；出现阻断项时仍打开应用预览对话框。应用前的冷备份不再是强制步骤：页面提供“应用前创建冷备份”开关，默认关闭；关闭时应用直接停服、发布并验证，失败不做自动恢复，并在任务错误中提示检查部署状态。

### 主机

- 保存新主机后停留在主机列表，通过提示进入连接设置。
- 指纹扫描由用户点击触发，仍需用户勾选并确认。
- 登录验证成功后停留在连接设置，通过提示进入主机环境。
- 指纹确认、Docker/root 安装确认和危险操作确认保持不变。

## 2. 实现方式

MOD 仍采用前端流程编排，复用 prepare/save/apply 命令。新建专服与世界配置改为后端合并语义：删除 `preview_instance_create` 和 `preview_world_apply` 公开命令；`create_instance`、`apply_world_config` 在同一 SSH 会话内先执行原只读检查，再执行接纳/应用事务。对外 DTO 不再携带 `planId`、`expectedPorts`、建议实例/目录、应用预览或 `desiredDigest`/`activeReleaseId`；前端保留完整 target、expectedRecordVersion、expectedRegistryRevision、operationId 和任务轮询；失败时保留已保存状态和任务现场。

## 3. 保留的安全边界

- 创建命令内的只读检查、端口/注册表检查、revision CAS 和 operationId 不变。
- SSH 指纹必须由用户确认。
- Docker 安装仍需要显式确认。
- 世界应用仍按检查结果执行保护备份、停止分片、发布后验证和失败回滚；MOD 应用仅在用户勾选“应用前创建冷备份”时创建备份并支持自动恢复。
- 恢复与删除仍使用确认弹窗。
- 所有请求继续绑定完整 target、上下文代次和最新请求序号。

## 4. 主机级 MOD 库

MOD 内容已提升到主机级公共库，实例通过主机库选择内容；详见 [主机级 MOD 库](host-mod-library.md)。备份已改为引用主机库；恢复使用主机库最新版本，缺失 MOD 提示但允许继续。

## 5. 尚未合并的后续项

以下仍按独立步骤执行，后续可继续合并：

1. 主机初始化与 Docker 安装合并为一个“准备主机”向导。
2. 无 Release 时在创建对话框内直接构建 Release。
3. MOD 配置编辑和候选版本采用直接提供“保存并应用/更新并应用”。
4. 世界配置应用成功后按用户选择自动启动专服。
5. 全流程主机级首次部署检查清单。
