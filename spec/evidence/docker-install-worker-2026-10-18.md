# Docker 安装 worker 失败排查

- 复现：旧 `ensure_repository()` 在签名密钥下载前发布新软件源，网络失败后残留软件源；回归测试在修复前失败、修复后通过。
- 修复：先下载并检查密钥 PEM 包络和大小，再发布缺失文件；网络暂时失败最多三次尝试，既有文件仍不覆盖。
- 诊断：任务失败保留实际执行阶段；下载、文件权限、空间、只读文件系统、缺少程序、任务数据错误映射为固定错误码，异常原文不写任务状态。
- 界面：失败状态及原因置于弹窗顶部，已有任务不再显示“符合安装条件”；核对亮暗主题 × 960×680/1480×920、Enter 提交、Escape 关闭与焦点回退。
- 自动验证：13 个 worker 测试覆盖临时目录中的完整主流程、任务失败阶段、网络异常分类/重试、格式异常、文件保护、APT 删除保护和运行验证。所有 apt/systemd/docker 调用均模拟，文件写入限制在测试临时目录；root 身份仅在 fixture 中模拟。
- 其他检查：Docker controller/预检隔离测试、前端测试/类型检查/构建、Rust fmt/check/test/clippy。Rust 两个独立 SSH/环境 fixture 测试保持忽略；Python 预检 root-only 场景在非 root 环境跳过。
- 限制：未访问用户服务器，尚未确定先前 `INSTALL_FAILED` 的具体异常。旧任务没有保留的信息无法补回；新建任务才使用新版 worker。此次验证不能替代 Ubuntu 26.04 的实际 APT 安装验收。
