# Release 管理列表 UI 改版规划

- 版本：1.0.5（规划）
- 日期：2026-11-09
- 状态：只规划列表显示与交互，未修改现有页面
- 关联：[前端实施](frontend-implementation.md)、[接口契约](api-contract.md)、[Release 管理页](../src/pages/ReleaseManagementPage.vue)

## 1. 当前问题

现有列表为五列网格：

```text
版本 | 固定镜像 | 验证状态 | 创建时间 | 操作
```

主要问题：

1. **“固定镜像”列名与内容不符**：当前显示的是镜像仓库名（如 `hungerdesolate/dst-runtime`），没有显示镜像 digest；“固定”也不是用户需要理解的词。
2. **缺少版本身份**：只显示 `dstBuild`，同 build 的多次构建无法区分；`releaseId` 虽然存在于数据中，但没有显示或只在 title 中。
3. **状态列重复**：`StatusLabel` 已经显示“已通过/待验证”，下面又重复一个“镜像”勾选步骤；运行验证移除后，这个步骤没有额外信息。
4. **操作列过宽且空置**：未验证版本显示“验证镜像”，已通过版本操作区几乎为空，删除按钮被推到最右侧；列宽仍固定预留 260px。
5. **长镜像名挤压布局**：`release.image` 在 960 宽度下换行或压缩其他列。
7. **技术信息没有降噪**：镜像完整字符串直接占据主视觉；digest、Release ID 等更适合作为次级信息或 title。
8. **空状态已精简**：当前只显示“暂无 DST Release”，这个方向保留。

## 2. 设计目标

1. 第一眼看清：**哪个 DST 版本、是否已通过、对应哪个镜像、何时创建**。
2. 同一 DST build 的多次构建可通过短 Release ID 区分。
3. 操作数量降到最少：未验证才有“验证镜像”，删除始终在最右。
4. 不增加摘要条，避免列表上方出现重复统计。
5. 技术字段默认截断/次级显示，完整值通过 `title` 查看，不增加详情页。
6. 宽屏表格、窄屏卡片；在 960×680 下不出现整页水平滚动。
7. 继续使用现有 StatusLabel、CSS Token、Lucide，不引入新组件库。

## 3. 推荐布局

### 3.1 宽屏（≥ 1100px）

```text
DST Release 管理
                                          [检查 DST 更新] [清理磁盘] [构建镜像] [刷新]

版本                 状态      镜像                          创建时间       操作
────────────────────────────────────────────────────────────────────────────
762172               已通过    hungerdesolate/dst-runtime    11-09 10:42    [删除]
Release 35a2e6bd                sha256:e948e647…
────────────────────────────────────────────────────────────────────────────
756039               待验证    hungerdesolate/dst-runtime    11-08 18:20    [验证镜像] [删除]
Release 1a2b3c4d                sha256:ab12cd34…
────────────────────────────────────────────────────────────────────────────
```

列定义：

| 列 | 内容 | 规则 |
| --- | --- | --- |
| 版本 | `dstBuild` 主文本；下一行 `Release <releaseId 前 8 位>` | build 用等宽数字；Release ID 完整值放 title |
| 状态 | `已通过` / `待验证` | 复用 StatusLabel；不再重复“镜像”步骤 |
| 镜像 | 镜像仓库名 | 超长省略；完整值放 title |
| 创建时间 | 本地日期时间；无值显示 `—` | 使用统一时间格式 |
| 操作 | 未验证：`验证镜像`；已通过：无验证按钮；删除图标固定最右 | 删除始终单独分组 |

建议网格：

```css
grid-template-columns:
  minmax(150px, .9fr)   /* 版本 */
  minmax(92px, .55fr)   /* 状态 */
  minmax(220px, 1.6fr)  /* 镜像 */
  minmax(112px, .65fr)  /* 创建时间 */
  minmax(150px, .8fr);  /* 操作 */
```

### 3.2 窄屏（960–1099px）

隐藏表头，改为卡片行：

```text
┌──────────────────────────────────────────────┐
│ 762172                         [已通过] [删除] │
│ Release 35a2e6bd                              │
│ 镜像 hungerdesolate/dst-runtime                │
│ sha256:e948e647… · 2026-11-09 10:42           │
└──────────────────────────────────────────────┘

┌──────────────────────────────────────────────┐
│ 756039                         [待验证] [删除] │
│ Release 1a2b3c4d                              │
│ 镜像 hungerdesolate/dst-runtime                │
│ sha256:ab12cd34… · 2026-11-08 18:20           │
│                              [验证镜像]        │
└──────────────────────────────────────────────┘
```

规则：

- 第一行：版本 + 状态 + 删除；未验证时第二行显示“验证镜像”。
- 第二行：短 Release ID。
- 第三行：镜像仓库名。
- 第四行：创建时间。
- 不使用横向滚动；长文本 `text-overflow: ellipsis` + title。

### 3.3 空状态与异常状态

| 状态 | 显示 |
| --- | --- |
| 无 Release | 只显示“暂无 DST Release”，不显示构建按钮和说明文案 |
| 读取中 | “读取 Release…” |
| 列表失败 | 顶部 `environment-error`，保留已有行或空状态 |
| Docker 不可用 | 顶部 `environment-error`；构建按钮禁用 |
| 正在构建 | 右下角浮动任务卡，双层条纹进度；列表保持可读 |
| 未验证行 | 状态“待验证”，操作“验证镜像” |
| 验证进行中 | 行内显示脉冲点 + “检查镜像…”，按钮禁用 |
| 验证失败 | 行内短错误 + 可重试“验证镜像” |
| 删除确认 | 现有删除 Dialog 不变 |

## 4. 交互调整

### 顶部操作

- 主操作：`构建镜像`
- 次操作：`检查 DST 更新`、`清理磁盘`
- 图标操作：刷新
- 顺序建议：检查 DST 更新 → 清理磁盘 → 构建镜像 → 刷新；构建是主路径，清理是低频危险操作，合并构建缓存与可回收 Release 后只保留一个入口。

### 行操作

- 未验证：`验证镜像` 是唯一行内主操作。
- 已通过：不再显示验证按钮，状态列已经表达结果。
- 删除：图标按钮固定最右，保留确认 Dialog；不与验证按钮混在同一组。
- 行内错误/成功提示放在操作列下方，不挤占其他列。
- 不新增“复制 digest”“详情”按钮；完整值通过 title 查看，避免列表操作过多。

### 排序

- 默认按 `createdAt` 降序；无 `createdAt` 的旧数据排在后面。
- 同一时间按 `dstBuild` 降序。
- 首期不提供用户手动排序。

## 5. 文案

| 位置 | 文案 |
| --- | --- |
| 页面标题 | `DST Release 管理`（保留） |
| 列头 | `版本` / `状态` / `镜像` / `创建时间` / `操作` |
| 未验证状态 | `待验证` |
| 已验证状态 | `已通过` |
| 验证按钮 | `验证镜像` |
| 验证中 | `检查镜像…` |
| 空状态 | `暂无 DST Release` |
| 删除按钮 | `删除 DST Release`（aria-label 保留） |

不再使用：

- `固定镜像`
- `可选运行验证`
- `镜像` 勾选步骤
- `运行验证通过`

## 6. 可访问性

- 优先使用语义化 `<table>`；若保留 grid，需要补 `role="table"`、`role="row"`、`role="cell"` 或改用原生表格。
- 删除图标必须有 `aria-label` 和 title。
- 未验证按钮支持 Tab/Enter；行内反馈使用 `role="status"` / `role="alert"`。
- 长文本截断时保留 title，不用纯颜色表达状态。
- 亮/暗主题、960×680、1480×920 验收；960 下无横向滚动。
- 减少动态效果时，验证脉冲和构建条纹停止动画。

## 7. 实现范围

只改前端展示，不需要后端字段变化：

| 文件 | 改动 |
| --- | --- |
| `src/pages/ReleaseManagementPage.vue` | 列表结构、响应式布局、行操作、截断与 title |
| `src/style.css` 或页面 scoped CSS | 仅补充/调整 Release 列表样式 |
| `scripts/test-build-tasks-ui.mjs` | 增加列头、空状态、行操作断言 |

预计工作量：0.5–1 人日（不含真实主机的视觉验收）。不做后端和安装包改动。

## 8. 已确认决定

- 放弃 Element Plus 迁移，继续使用自有组件和 CSS Token。
- 版本列显示短 Release ID。
- 镜像列只显示镜像仓库名，不显示 digest。
- 不增加“版本总数 / 已通过 / 待验证”摘要条。
- 960 宽度下改为卡片行。
- 删除按钮保留在行内，固定在操作区最右。
